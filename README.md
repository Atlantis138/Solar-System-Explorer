# 太阳系探索者 (Solar System Explorer V9.0)

这是一个基于 React 19、TypeScript 和 D3.js 构建的交互式 2D/2.5D 太阳系模拟应用。它结合了精确的天文算法（Astronomy Engine）与 Google Gemini AI，旨在提供既科学严谨又具有视觉吸引力的天文探索体验。

## 🌟 项目简介

该项目并非单纯的静态展示，而是一个实时轨道物理模拟器。它支持：
*   **双重渲染模式**：示意图模式（Schematic，易于观察）与真实比例模式（True Scale，感受宇宙的浩渺）。
*   **AI 增强**：集成 Google Gemini API，提供关于天体的实时问答和搜索接地（Grounding）。
*   **天象搜寻**：能够计算并预测行星连珠、凌日等罕见天象。
*   **虚拟漫游**：支持全方位视角的相机控制（偏航/俯仰）和类似 3D 的透视效果。
*   **自定义天体**：允许用户通过 UI 添加自定义的行星、卫星或小天体。

## 💾 数据架构与自定义天体

本项目采用灵活的数据加载机制，支持“官方数据”与“用户数据”的运行时合并。

### 1. 数据来源
*   **静态文件**：`public/data/solar_system.txt` 包含系统默认的行星定义。
*   **真实恒星**：`public/data/real_stars.json` 包含 XHIP 的 8,874 颗 ≤6.5 等恒星及 2 颗星座连线补充星（共 8,876 颗，J2000 RA/Dec）。
*   **用户存储**：浏览器 `LocalStorage` (`custom_bodies_text`) 存储用户添加的自定义天体。

### 2. 格式规范
所有天体（无论是默认还是自定义）均采用统一的 **Block-based 文本格式**。
解析器位于 `utils/DataLoader.ts`。

**格式示例：**
```text
[PLANET]
id: my_planet
name: 自定义行星
englishName: My Planet
color: #00ff00
radius: 5
relativeRadius: 1.0
elements: 1.52 0.09 1.85 49.5 286.5 19.4
# elements顺序: a e i N w M
```

### 3. 对象管理器 (Object Manager)
用户可以通过设置面板打开“对象列表”。该管理器 (`ObjectManager.tsx`) 允许：
*   查看所有已加载天体的状态（是否解析成功）。
*   **添加自定义天体**：提供模板编辑器，支持行星、矮行星、彗星、卫星和光环的快速定义。
*   **持久化**：保存的数据会写入 LocalStorage，刷新页面后依然存在。

## 🧊 3D 投影与天球背景

本项目在 2D Canvas 上实现了伪 3D 投影引擎 (`core/projection.ts`)。

### 1. 坐标系旋转
相机位置固定，通过旋转整个世界坐标系来模拟视角变化：
*   **Yaw (偏航)**：绕 Z 轴旋转 (0° - 360°)。
*   **Tilt (俯仰)**：绕 X 轴旋转 (-90° 至 +90°)。
    *   +90°: 北极俯视 (Top-down)
    *   0°: 黄道面侧视
    *   -90°: 南极仰视

### 2. 天球背景 (Celestial Sphere)
背景星空 (`StarField.tsx`) 并非静态图片，而是实时计算的 3D 点集：
*   **数据源**：赤经 (RA) 和赤纬 (Dec) 数据。
*   **转换**：
    1.  将 RA/Dec 转换为单位球上的笛卡尔坐标 $(x, y, z)$。
    2.  应用与太阳系天体相同的旋转矩阵 (Yaw & Tilt)。
    3.  投影到屏幕空间。
这确保了当用户旋转相机查看行星轨道时，背景星空会以正确的角速度同步旋转，提供沉浸式的空间感。

### 3. 全天星表与清晰度

* 默认开启真实星空：8,876 颗恒星，88 个星座、743 段连线；巨蛇座的两部分合并为一个星座。星座连线为传统示意图，并非 IAU 星座边界。
* 设置 → 天球可调整极限星等（3.0–6.5）、恒星亮度、中文/双语名称与连线。开启连线时保留构图恒星；关闭真实恒星后才显示程序生成的装饰星空，避免混淆真实位置。已有保存的设置继续生效。
* 名称来自星表，仅标注有名称且亮于 3.5 等的恒星，亮星优先、自动避让；不把 HIP 编号冒充英文名称。部分恒星没有中文名，中文模式不显示这类名称。
* Canvas 按实际 `devicePixelRatio` 分配像素，响应容器尺寸、浏览器缩放与跨屏 DPR 变化；字体使用 12px，标签独立亮度并增加深色描边。移除了父层亮度滤镜和标签的重复透明度衰减。
* 赤道坐标先转黄道坐标，再旋转投影；赤道网格使用同一黄赤交角方向。连线预先采样为球面短弧，并在可见半球边缘裁切。
* 仍使用 Canvas 2D，无需 WebGL。坐标与连线缓存，静止天球不持续重绘；星表和连线作为本地静态文件随应用发布。
* 数据来源为 [d3-celestial](https://github.com/ofrohn/d3-celestial) 整理的 XHIP（Anderson & Francis, 2012）。固定 J2000 坐标，不计算恒星自行或岁差；星色由 B−V 近似计算。来源版本、输入 SHA-256 和统计见 `public/data/catalog-sources.json`，许可见 `public/data/d3-celestial-LICENSE.txt`。

重建数据：从来源清单所列固定 Git revision 的 `data/` 下载 `stars.8.json`、`starnames.json`、`constellations.json`、`constellations.lines.json`，再从仓库根目录下载 `LICENSE`，放入 `work/catalog/`，运行 `python scripts/build-star-catalog.py work/catalog`。运行 `npm test` 检查星表、连线引用与投影裁切，`npx tsc --noEmit` 检查类型，`npm run build` 构建发布文件。

## ⚙️ 渲染压力与性能配置

为了兼容不同性能的设备，项目引入了分级渲染策略 (`core/renderConfig.ts`)。

### 共享渲染优化

* `core/orbitCache.ts` 缓存世界坐标轨道：普通轨道按轨道参数复用；支持的高精度行星按 30 天窗口缓存曲线求值，每颗天体最多保留 4 个曲线变体。跳转日期、修改参数和切换精度会选择相应缓存。卫星轨道保持父天体相对坐标。高精度轨迹是窗口内的绘图近似，行星当前的位置仍逐帧计算。
* `core/canvas.ts` 与 `hooks/useCanvasDraw.ts` 统一 CSS 像素绘图和 DPR 后备像素，尺寸不变时不重新分配画布；暂停时也响应容器尺寸和屏幕像素比变化。天球使用同一画布准备工具。
* `core/asteroidBelt.ts` 在 Canvas 内批量绘制确定性的小行星点集，按屏幕尺度与档位选择最多 2,000 颗并剔除屏幕外粒子。两种比例模式共用点集与开普勒示意公转；切换模式或开关不会重新随机生成。粒子为示意数据，不是真实小行星星历。
* `PlanetRing.tsx` 与 `core/rings.ts` 将环按相机深度分成后半环和前半环，与所属行星按顺序绘制。环的可见性独立于轨道线开关，沿用原有环倾角和颜色；近距离仍采用与行星圆盘一致的局部投影近似。
* 行星列表保持稳定引用，相机跟随的旋转中心由当前时刻直接推导，避免每个时间步再通过状态更新重画一次。少量可交互天体保留 SVG；真实比例模式补充透明点击区域。

开发环境同视角、同 2 秒播放采样：高精度模式的 `HelioVector` 调用由约 36,568 次降至 1,936 次；示意模式 SVG 圆节点由 1,017 个降至 17 个。该数字用于定位重复工作，不代表所有设备的帧率或固定加速比。自动回归覆盖缓存、星环分面、DPR 与粒子剔除，运行 `npm test`。

### 渲染质量与观察位置

设置按行星与卫星、矮行星、彗星与小行星分组。保留原有设置键兼容已保存偏好，
分组仅决定细节预算，不再以绕日半长轴或太阳中心的全局缩放阈值决定可见性。
节能更早淡出过小细节，平衡平滑过渡，完整保留视锥内的微小天体；选择、固定与
跟随的目标优先保留。两种比例模式分别配置三档阈值，所有档位都剔除画面外对象。
天体名称跟随已显示的标记，不再按真实圆盘的像素半径额外隐藏，也不重复叠加透明度。

`core/sceneView.ts` 是统一观察模型：从姿态、视窗、平移与缩放计算 AU 坐标的相机
位置，提供投影、视锥线段裁剪、圆盘边界和系统包围体判断。默认缩放移动相机，
平移在观察平面内移动相机；前景与无限远天球共用 72° 短轴视场。正交及固定距离
镜头模式保留。绘制仍采用 Canvas 2D + SVG，不依赖 WebGL。

`core/orbitGeometry.ts` 直接求值连续轨道，按当前视角细分至约 0.45 CSS 像素误差，
先做相机空间裁剪再透视除法，达到预算时中断未解析弧段而不连接错误长弦。
世界空间曲率范围可找到采样点之间狭窄的可见弧。高精度轨迹按时间窗口缓存求值，
普通与卫星轨迹保留解析椭圆。轨道明暗按观察距离连续变化，远处辅助线没有最低
亮度保底；长直段另按屏幕距离细分样式，避免亮度分段。`core/regionDrawing.ts` 独立绘制柯伊伯带与日球层顶：恢复虚线、沿弧排列的文字
和独立亮度。虚线段固定在空间圆弧上，随透视改变疏密、粗细与明暗，不使用屏幕等长虚线。
真实比例标签以 34 CSS 像素为基准，再按透视缩放；文字在屏幕像素坐标中绘制，
避免极小相机缩放导致字号超出浏览器上限；侧视时扩大字距，极端压缩时使用完整名称，
避免字符相互叠压。仍复用相机裁剪与自适应曲线。

## 行星—卫星共同质心

目录支持 `massRelativeToSun`（天体自身质量与太阳质量之比）、`orbitReference`
和 `ephemerisReference`。母体开普勒绕日元素标记为 `system-barycenter` 时描述整个
系统的质心；卫星的 `orbitReference: parent` 和半长轴描述卫星相对母体的轨道，
不是卫星绕质心的轨道半径。可选 `epochJD` / `periodDays` 指定元素历元与测得的周期。
缺少质量的卫星可作为示踪点；母体缺少质量时必须提供周期且会明确提示无法计算质心反作用。重复 ID、负质量、
无效参考中心或不支持的嵌套卫星会报告错误。

`calculatePlanetarySystem` 根据全部有效卫星质量求出母体偏移；可见性和细节档位不
参与质量计算。真实比例下绘制母体与卫星各自的局部轨道，点击详情右上角的“查看质心绕转”小按钮自动放大、跟随系统质心。此操作仅在真实比例
模式启用，普通模式按钮置灰并提示原因；退出真实比例后改为跟随天体自身。

高精度模式保留 Astronomy Engine 的地球位置，使用 `GeoMoonState` 和
`JupiterMoons` 提供的月球及木星四大卫星状态。引擎的冥王星系统位置按质心分配，
不对已有的天体中心星历重复扣除偏移。卡戎使用近圆、固定周期的近似轨道，不宣称
达到精密卫星星历精度；其他未被引擎覆盖的卫星沿用目录开普勒模型。
局部轨道线为瞬时密切轨道，多卫星系统绘制单颗卫星轨道时固定其他卫星的当时偏移。
该模型不进行全太阳系 N 体积分。参数来源和限制见 `public/data/system-sources.json`。

### 编辑目录与添加卫星

设置中的天体目录提供“编辑”“恢复内置数据”和“添加卫星”。内置修改保存在
`body_overrides_text`，新增对象保存在 `custom_bodies_text`，仅在当前浏览器生效。
ID 必须唯一；内置天体编辑保留 ID、类别与母体。每次保存前校验数值与关系。

例如为鸟神星添加假设卫星：先编辑鸟神星的 `massRelativeToSun` 并注明来源或假设，
再使用“添加卫星”填写唯一 ID、`parent: makemake`、卫星自身质量，以及以母体为
参照的 `elements: a e i N w M`（AU、度，J2000 黄道系）；可选 `epochJD`、
`periodDays` 明确相位历元与周期。没有可靠质量时不会自动猜测；可填周期预览示踪
轨道，但不能据此声称获得真实质心运动。新获得卫星且未显式指定参考中心的母体
默认采用系统质心轨道。显式 `orbitReference: body` 保留兼容行为。

质量、轨道或卫星成员改变后，该系统使用用户输入的开普勒近似参数，避免内置
精密星历覆盖编辑结果；其他系统继续使用高精度引擎。仍只支持一级母体—卫星关系，
不支持卫星再拥有卫星或完整 N 体相互摄动。目录与物理测试覆盖假设鸟神星卫星的
完整周期、质心质量守恒、缺失质量提示、保存与恢复，不将测试假设写入正式目录。

### 运动来源与显示模式

真实比例、矮行星/海王星外天体、彗星/小行星显示互相独立；旧偏好中的
`allowTrueScaleAllBodies` 不再参与任何行为，额外的兼容开关已移除。切换尺寸模式
只改变显示尺度，不切换天文算法。

位置计算按系统选择来源：未编辑且受 Astronomy Engine 支持的天体使用星历；
关闭引擎、没有相应星历或编辑了质量/轨道/成员的系统使用目录开普勒模型。
高精度母体与未受支持卫星的组合按“母体星历位置 + 相对开普勒位移”合成。
质量用于质心分配和未指定周期的卫星二体周期，行星绕日开普勒模型仍采用太阳
质量近似；没有全太阳系实时 N 体积分，也不会将三套绝对位置重复相加。

填写 `periodDays` 时明确优先使用该周期，不再叠加质量推算的角速度。卫星输入周期
与半长轴/质量推算的二体周期相差超过 2% 时提示核对，保留用户输入，不擅自改值。
天体详情的“运动依据”读取实际计算结果，区分母体系统位置和卫星相对运动来源。
场景、跟随和天象搜索共用系统位置接口；绘图轨道是结果的辅助表示，不回写为运动状态。


### 文字与渲染预算（2026-10-03）

场景文字统一使用 CSS 像素，不再把字号除以世界缩放倍数。天体名称位于独立 SVG
文字层（普通 12 px、重点目标 13 px），固定置于各自天体下方，不进行碰撞避让、
换位或按拥挤程度隐藏，避免移动视角时名称跳动。太阳系区域名称按
投影尺寸在 10–22 px 内缩放，区域过小时淡出；两种比例使用同一屏幕尺度规则。
恒星名称为 12 px，网格为 11 px，星座背景名称为 22–30 px。UI 辅助文字最低 10 px，
窄屏播放栏使用两行布局。

“整体画质”控制实际工作预算；旧的三个分类选项移入“按类别保留微小天体”，
继续使用普通/真实比例分别校准的屏幕可见性阈值。新字段 `sceneQuality` 缺省为平衡，
不覆盖已有分类偏好。全部档位共用相同的天文位置计算与经过时间，不降低星历精度。

天体与名称保留原生清晰度；星表、星座连线端点均不删减。轨道、粒子与天球独立

### 小天体目录与族群

`PlanetData` 描述单颗天体及行星环；`SmallBodyPopulation` 独立描述粒子族群的半长轴采样范围、分布、颜色和参考天体，不伪造一个族群的轨道、半径或质量。目录中的三个族群是小行星主带、木星特洛伊 L4/L5 群、柯伊伯带小天体。只有主带默认开启；主带不绘制名称。主带仅由天体目录中的 `showAsteroidBelt` 控制，不受小天体总开关影响。非主带族群统一使用 `showNonMainBeltPopulations`，同时受小天体总开关控制，可随「存为偏好」保存。

三群共用整体画质的 320 / 850 / 2,000 粒子预算，确定性采样、屏幕裁剪和基于观察者距离的淡出一致。环带示踪点使用有离心率和倾角的开普勒轨道；特洛伊群围绕实际木星位置前后约 60° 分布，并示意缓慢摆动。它沿用当前木星数据和引擎的计算结果，隐藏木星本体不会移走族群。此处不进行 N 体积分，粒子不是逐颗实测成员。柯伊伯带粒子开关与原有边界辅助线独立。

新增四颗内置小天体：智神星、爱神星、凯龙星、天涯海角。补充数据采用明确历元、周期的开普勒模型，开启高精度引擎也使用此后备模型；没有已知质量时不填入猜测值。轨道、尺寸及转换依据见 `public/data/catalog-additions-sources.json`。凯龙星来源为太阳系质心参考系，先转换状态向量到日心参考系，再推导目录中的轨道，避免直接混用；天涯海角的圆点仅按最大半轴示意，未表达真实接触双叶形状。灶神星从矮行星改归小行星，同时兼容旧版的本地编辑。环名称均标明所属行星；天王星与海王星条目表示原模型的整体环区，而非只代表某一条窄环。


### 目录与轨道层级（2026-10-04）

族群以「小行星与其他小天体」分组下的紧凑条目展示，名称旁标注族群；参数按钮打开独立的分布字段面板。大 Logo 已移除，目标、缩放、倾角和方位角信息移至左上角。Arrokoth 统一使用「天涯海角」译名；旧译名的本地编辑随载入迁移，轨道参数不变。

`core/orbitCategories.ts` 共用目录分类、默认可见度和线宽层级。默认轨道可见度为行星 100%、天然卫星 85%、矮行星 60%、彗星 40%、小行星 30%；相应线宽乘数为 1、0.95、0.8、0.67、0.55。线宽乘数作用于原有远近深度及观察者距离样式，不改变投影或运动。两种尺寸模式共用类别层级，保留各自原有基础线宽。选中目标可强调，但全局和类别设置为 0 时仍不画轨道。

各目录分组标题旁的小滑块只改变该类轨道，不改变天体、名称或族群粒子。它与设置里的全局轨道可见度相乘，随「存为偏好」保存为 `orbitCategoryOpacity`；旧偏好或仅存部分类别时逐项回落到默认值。行星环是实体环面，不显示轨道滑块。关闭某类轨道会在投影前剔除对应曲线。

### 星际来访与彗尾

目录沿用物理类别：`1I/ʻOumuamua`（奥陌陌）放在 `[ASTEROID]`，`2I/Borisov`、`3I/ATLAS` 放在 `[COMET]`。`interstellar: true` 只标记已确认的星际来源；普通彗星即使瞬时离心率略大于 1，也不会自动变成星际天体。目录的年份小按钮跳转到同组轨道参数的近日点，暂停播放、启用该类并跟随目标。近日点以外仍按时间计算其远离过程，不按年份突然隐藏或循环重置。

自定义双曲线沿用 `elements: a e i N w M`：`a < 0`、`e > 1`，`q = a(1-e)` 为正。可使用 `epochJD` 与该历元的 `M`，或添加 `perihelionTimeJD` 并把 `M` 设为 `0`；两者有冲突时校验拒绝保存。双曲线不能填写 `periodDays`，目前不作为卫星轨道使用；`e = 1` 的抛物线暂不支持。示例：

```text
[COMET]
id: sample_visitor
name: 示例星际彗星
interstellar: true
radius: 2
relativeRadius: 0.00005
perihelionTimeJD: 2460977.982533267
elements: -0.2639353538137568 6.139311027021769 175.1131066568337 322.1561096899903 128.0082001729325 0
```

双曲线传播解 `e sinh(H) − H = M`，不把平近点角对 360° 取模。运动和轨迹共享相同几何定义；开放轨迹不首尾相连，继续使用相机视锥裁剪和自适应采样，跟随远去的天体时扩展缓存的绘制范围。高精度引擎支持的行星仍走原星历；这三颗小天体统一使用目录中的日心开普勒近似，不会被两套位置重复叠加。`public/data/interstellar-sources.json` 记录公开 JPL 数据缓存、快照标识、轨道历元和尺寸假设。本次未联网直取 JPL；这是历元附近的瞬时轨道近似，远期外推不包含行星摄动或喷气作用。来源 JD 为 TDB，当前日期系统近似按 UTC 映射，2017–2025 年约差 69 秒，不用于精确天象预报。

彗尾是低成本的显示示意：离子尾背向太阳，尘尾略向运动后方弯曲，活动程度随日心距离平滑降低。它不改变轨道，也不声称模拟真实亮度、尘埃动力学或观测尾长。普通与真实比例共用 AU 空间投影，普通模式适配放大的彗核；真实模式保留距离投影。Canvas 与主画面同步更新，节能／平衡／完整分别最多 8／16／24 段每条尾，不使用粒子系统或模糊滤镜；关闭后不挂载彗尾图层。

“显示彗星与小行星”展开后三行紧凑选项：小行星（天体、非主带族群）、彗星（天体、彗尾）、星际天体（天体、彗尾若有）。星际天体不受普通彗星／小行星行控制；两行彗尾分别使用 `showCometTails` 与 `showInterstellarTails`，且只有相应天体开启时才绘制。总开关关闭时保留子偏好并隐藏上述对象，但主带始终独立，由目录控制，默认开启。`smallBodySettingsVersion: 2` 迁移旧偏好：保留主带选择，把原彗尾偏好带入两行，合并原有效的非主带族群选择。

三类天体分别拥有轨道开关：`showAsteroidOrbits`、`showCometOrbits`、`showInterstellarOrbits`，默认均开启。它们在生成轨道几何前生效，且与全局／目录轨道亮度相乘；不影响本体、族群或彗尾。星际轨道开关按来源优先匹配，不受普通分类轨道开关影响。轨道与彗尾控件只在对应“天体”勾选时显示，收起保留偏好；窄屏在同一类别内自动换行。普通彗星默认带彗尾，星际彗尾默认关闭（已有明确保存的选择保留）。
